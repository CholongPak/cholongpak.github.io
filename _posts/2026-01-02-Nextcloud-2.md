## Step 1: AWS VPC & Networking Setup

### 1.1 VPC Configuration

I created a VPC named "Nextcloud-vpc" with a CIDR block of 10.0.0.0/16 (IP range 10.0.0.0 to 10.0.255.255). _[(CIDR: Classless Inter-Domain Routing)](https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing)_ 

To ensure high availability across the region, I configured the network with:

- Two Availability Zones: us-east-1a, us-east-1b. Spreading resources across multiple zones to prevent service interruption.  
- Two Public Subnets: These allow the EC2 instance to communicate with the internet.  
- S3 Gateway Endpoint: The VPC can communicate directly with Amazon S3 without leaving the AWS network, improving both security and performance.

### 1.2 Security Groups

Security is a top priority for this project. 
I implemented two distinct Security Groups to enforce the principle of least privilege:

- NextcloudSecurityGroup: This group controls traffic to the EC2 instance. I opened the following ports to the public (0.0.0.0/0):  
        - SSH (22): For secure remote server management.  
        - HTTP/HTTPS (80, 443): For standard web access to the Nextcloud interface.  
        - Custom TCP (8080, 8443): Specifically required for the Nextcloud All-In-One (AIO) management dashboard.  

![nextcloud_security_group](/assets/img/aws_cloud/nextcloud_security_group.png)


- EFSSecurityGroup: This group manages access to the Elastic File System. It is configured to allow NFS (Port 2049) traffic only from the NextcloudSecurityGroup, ensuring that only the authorized application server can access the configuration files.
