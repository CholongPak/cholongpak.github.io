I integrated the server across multiple platforms to ensure a seamless and unified data experience.  

### 8.1 Desktop Client Setup & Usage

The desktop client acts as the primary bridge between my local workstation and the AWS-backed storage, enabling automated synchronization and offline access.

- Installation: Downloaded the official client from Nextcloud Install for my OS (Windows 10). https://nextcloud.com/install/#install-clients

![download_nextcloud_desktop](/assets/img/aws_cloud/download_nextcloud_desktop.png)

- Configuration: Open the Nextcloud Desktop Client and use the server address.

![login_nextcloud](/assets/img/aws_cloud/login_nextcloud.png)

- Authenticated using a non-admin user for better security hygiene.
- Custom Sync: The client will default to syncing everything in the root directory. The user can customize this to sync only specific folders.
- Status Icons to provide real-time feedback on the synchronization state of each file.

![pc_screen](/assets/img/aws_cloud/pc_screen.png)
![s3_screen](/assets/img/aws_cloud/s3_screen.png)

### 8.2 Mobile Client Setup & Usage

The mobile integration provides a secure, self-hosted alternative to commercial services like Google Photo or iCloud, allowing for automated media backups.

- Installation: Downloaded the app file from Google Play Store (OR the Apple App Store)

![nextcloud_mobile](/assets/img/aws_cloud/nextcloud_mobile.png)

- Configuration: Open the app and enter the server address and user credentials. It has features like auto-upload for photos and videos.

![mobile_screen](/assets/img/aws_cloud/mobile_screen.png)

- File Management: Use the "+" button to upload photos, videos, or other documents. In settings, enable "Instant Uploads" to automatically back up a camera roll to a designated folder in the Nextcloud.

#### Troubleshooting Note: Nextcloud S3 Upload Failure

During the final implementation phase, I encountered a critical issue regarding storage integration. 

The issue prevented file uploads to the S3 bucket, creating a "400 Bad Request" error in the logs with the exception InvalidStorageClass. This occurred because the Storage Class field in the NextCloud External Storage configuration was incorrectly populated with the string "admin," which is not a valid Amazon S3 storage type. 

The issue was resolved by deleting this field in the external storage settings, allowing NextCloud to revert to the default AWS storage class (STANDARD) and successfully resolve the issue. 

![upload_issue1](/assets/img/aws_cloud/upload_issue1.png)
![upload_issue2](/assets/img/aws_cloud/upload_issue2.png)

>_**Storage Class**: A setting in Amazon S3 that determines the storage redundancy and cost model (e.g., STANDARD, INTELLIGENTTIERING, or GLACIER). Choosing an invalid class causes the S3 API to reject the request_
