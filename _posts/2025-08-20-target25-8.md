**D11. Semi-Final Boss**

**Question**
>**Introduction**  
>The trail has led us to a host owned by a new Personalyze.io employee, John Miller, only a few weeks into onboarding. The investigation team has remotely pulled forensic artifacts from the machine and found... almost nothing. The host is immaculate, even the browser history is empty. It's like John has done no work at all. There's no malware, no C2 traffic, no evidence of compromised credentials, no remote access software.  
>
>All that's left to do is analyze the Windows registry hive that was collected.  
>Can you find at least ONE suspicious registry key to keep this investigation moving forward?  
>The registry hive is attached to the challenge.  
>
>**Flag format**  
>The flag for this challenge is a registry key path, e.g HKCU\Software\Policies\Microsoft\Windows\WindowsCopilot\TurnOffWindowsCopilot  
>
>Don't worry about the specifics, we'll be generous in what we accept. But don't try to brute force the answer, you have limited guesses.  
>
>**Required tools**  
>RegistryExplorer, hivexsh, or similar Windows registry analysis tool  
>
>**DO NOT load the registry into your local registry**  
>Doing so could mess your Windows machine up!!!  
>Practice good Incident Response analyst practices and use a tool for extracting the contents of the registry hive file, like "regripper" or the other tools above (google others), preferably in a VM if you can.  
>
>**Additional resources**  
>https://www.cybertriage.com/blog/windows-registry-forensics-cheat-sheet-2025/  


**How I found the flag**

1. This was my first time working with Windows Registry forensics, so I initially didn’t know what looked suspicious versus what was normal. Fortunately, the reference, forensics-cheat-sheet, explained which Registry locations I should examine to find the flag.
![registry fornsic](/assets/img/target2025/target2025_d11_0.png)
2. After reading the reference, I started suspecting that a USB stick might have been used in the attack. I noticed a change date of March 4, which seemed possibly evidence. However, I wasn’t certain. Since the challenge only allowed 50 attempts, the only way to check was to try entering paths to see if they matched the flag. This first attempt failed.
![registry fornsic - usb sticks](/assets/img/target2025/target2025_d11_1.png)
3. I also noticed a Microsoft folder and a CTF folder that looked suspicious. I tested that path as a possible flag, but it didn’t work. At this point, I had already used nearly 20 attempts. 
![registry fornsic - CTF folder](/assets/img/target2025/target2025_d11_2.png)  
4. Next, I checked the Services entries. Some items had June timestamps. I googled the service names one by one but didn’t find anything malicious.
![registry fornsic - Service](/assets/img/target2025/target2025_d11_3.png)
5. I reviewed the HID (keyboards, mice, game controllers) and SWD (sound, video) sections. I focused only on items with Marcj 4 timestamps, since a date range hint was in the question. 
![registry fornsic - HID](/assets/img/target2025/target2025_d11_4.png) 
6. One of the them had a FriendlyName: TinyPilot (HD Audio Driver for Display Audio). I had never heard of this before, so it stood out. 
![registry fornsic - SWD - FriendlyName - TinyPilot](/assets/img/target2025/target2025_d11_5.png) 
7. Searching online, I learned that TinyPilot enables remote access to a system, which made it seem suspicious and likely related to the attack.
![registry fornsic - TinyPilot](/assets/img/target2025/target2025_d11_6.png) 
8. Finally, I used the search function to see if there were other registry paths related to TinyPilot. I found multiple paths. Any of these could potentially be the correct flag.
![registry fornsic - Paths](/assets/img/target2025/target2025_d11_7.png)

**Flag: HKLM\System\ControlSet001\Enum\SWD\MMDEVAPI\{0.0.0.00000000}.{b0f20925-97b3-4a58-bdce-adc367e8ec6d}**
