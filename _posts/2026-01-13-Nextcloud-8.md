I implemented a multi-layered security approach, covering both the application level and the AWS infrastructure level.  
Application (Nextcloud), Infrastructure (AWS), and Data (S3/EFS)  

### 7.1 Application Security & Validation

I verified the security of the Nextcloud installation using official diagnostic tools to ensure the environment is hardened against common web vulnerabilities.

Nextcloud Security Scan: I ran a scan via scan.nextcloud.com. This service validates SSL/TLS configurations and checks for essential security headers like HSTS. Achieving A+ ensures that the Duck DNS domain is properly secured.

>_**HSTS**: HTTP Strict Transport Security, is a web security policy that forces browsers to connect to a website only via secure HTTPS connections, preventing insecure HTTP usage and protecting against man-in-the-middle attacks._  
>_**A Man-in-the-Middle attack**: Cyberattack where a hacker secretly intercepts and alters communication between two parties who believe they're communicating directly._

### 7.2 AWS Infrastructure Security

I configured the Security Groups according to the official Nextcloud AIO requirements, ensuring that each port serves a specific operational purpose while maintaining the principle of least privilege.

**Web Services & Certificate Management:**

Port 80 (TCP): Open for the ACME HTTP-01 challenge (SSL). It is essential for obtaining and renewing Let's Encrypt certificates for the Mastercontainer and Nextcloud. It also handles redirects to the secure HTTPS interface.

Port 443 (TCP/UDP): Open for standard HTTPS traffic and HTTP/3 support (via UDP). Also, the primary port for the Apache container. 

Port 8080 (TCP): The initial management interface. https://[IP]:8080 for the first-time setup. It uses a self-signed certificate for local security.

Port 8443 (TCP): The management interface with a valid domain certificate. 

Backend & Data Layer (Internal): Port 2049 (TCP). It is Used for EFS (NFS) communication. This port is strictly restricted via Security Group Chaining, allowing inbound traffic only from the Nextcloud EC2 instance, effectively isolating the data layer from the public internet.

### 7.3 Data Privacy & Encryption

To ensure the privacy of personal files, encryption was implemented for both data at rest and data in transit.

S3 Bucket Privacy: The S3 bucket is configured with "Block all public access." User data is only accessible through the Nextcloud application layer, and direct external access to the S3 URL is strictly prohibited.

In-Transit Encryption: SSL/TLS. All web traffic is encrypted via Let's Encrypt certificates.
>_**SSL/TLS**: SSL (Secure Sockets Layer) and TLS (Transport Layer Security) are cryptographic protocols that secure communication over a network by encrypting data between a client (e.g., browser) and a server, often denoted by HTTPS. TLS is the modern, secure successor to SSL, which is deprecated._

Automated Backups: I established a centralized backup plan via AWS Backup for EBS, EFS, and S3, providing a recovery point in the event of accidental deletion or a security incident.
