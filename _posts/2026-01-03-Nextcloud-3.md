## Step 2: Configuring EFS & S3 Storage
This project utilizes a dual-storage strategy to balance high performance for system files and cost-effective scalability for user data.

### 2.1 Amazon EFS: The Persistent Configuration Files

Amazon EFS's primary role is to store Nextcloud’s configuration files, ensuring data survives even if the EC2 instance is replaced. 

- Basic Settings: Created a file system named NextcloudEFS within the Nextcloud-vpc with Regional availability.
- Advanced Customization: 
        - Lifecycle Management: To optimize costs, I configured a lifecycle policy to transition files to the Infrequent Access (IA) storage class after 7 days of inactivity.
- Performance & Throughput: Configured with General Purpose mode and Bursting throughput.
- Security: Encryption was enabled to ensure data protection.
- Network & Mount Targets: To ensure accessibility across the VPC, I manually created mount targets for each of the two public subnets. Each mount target was specifically assigned the EFSSecurityGroup, which limits access to the EC2 instance via the NFS port (2049).

>_"Mount" is the process of attaching a remote or external storage device (like Amazon EFS) to a specific directory on a server’s file system (/mnt/efs)_  
>_"Mount Target" is an endpoint that provides an IP address for an EC2 instance to connect to an EFS file system._

### 2.2 Amazon S3: The Primary User Data Store

While EFS handles system files, Amazon S3 is used as the primary backend for all user-uploaded content (photos, documents, etc.).


- Bucket Configuration: I created a globally unique S3 bucket with Versioning enabled to protect against accidental deletions or overwrites.
- Access Control: The bucket is kept Private, with all public access blocked. Access is granted specifically to the EC2 instance using an IAM LabRole.
- Lifecycle Management: To optimize costs, I implemented a Lifecycle Rule to transition objects to Intelligent-Tiering 0 days after creation, allowing AWS to automatically move infrequently accessed files to cheaper storage classes.
- S3 Gateway Endpoint: By using the S3 Gateway Endpoint created during the VPC setup, data travels between the EC2 instance and the S3 bucket over the private AWS network, avoiding the public internet for better security and lower latency.

**S3 Bucket Policy**

1. After creating S3 bucket, go to “IAM” -  “Roles” and search “LabRole”. Copy “ARN” 
![labrole](/assets/img/aws_cloud/labrole.png)

2. Go to the nextcloud S3 bucket and select “Properties” tab. Copy “ARN”
![S3ARN](/assets/img/aws_cloud/S3ARN.png)

3. Then select “Permissions” tab. Under Bucket Policy, click “Edit” then click “Policy generater”
![edit_bucket_policy](/assets/img/aws_cloud/edit_bucket_policy.png)

4. Type of Policy: S3 Bucket Policy  
        Effect: Allow  
        Principal: Paste LabRole ARN  
        Actions: All Actions  
        Amazon Resource Name (ARN): Paste S3 bucket ARN  

5. Copy the script and paste that into the policy and save change.
![S3_policy1](/assets/img/aws_cloud/S3_policy1.png)
![S3_policy2](/assets/img/aws_cloud/S3_policy2.png)
![S3_policy3](/assets/img/aws_cloud/S3_policy3.png)

**Lifecycle Rule**

1. Go to the "Management" tab of your new bucket and click "Create lifecycle rule".
2. Rule name: Move-to-Intelligent-Tiering  
        Scope: Apply to all objects in the bucket.  
        Transitions:  
                Check "Move current versions of objects between storage classes".  
                "Transition to Intelligent-Tiering": 0 days after creation.  
3. Click "Create rule".
