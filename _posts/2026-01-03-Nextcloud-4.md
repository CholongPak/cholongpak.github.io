With the networking and storage infrastructure ready, the next step is to launch EC2 instance, assign a permanent entry point via an Elastic IP, and configure Duck DNS for stable domain access.

### 3.1 EC2 Instance

I provisioned a virtual server (EC2) with the following specifications to meet the requirements of a containerized Nextcloud environment:

- Instance Type: t2.medium (2 vCPUs, 4 GB RAM)
- Operating System: Used Ubuntu Server 22.04 LTS for its stability and broad support for Docker.
- Storage: Increased the root EBS volume to 16 GB (gp3) to ensure adequate space and performance for the OS and Docker engine.
- Security: Attached the NextcloudSecurityGroup to control inbound traffic and used a secure Key Pair for SSH access.
- EFS Mount: I used an AWS User Data script. This script automatically installs the necessary utilities and mounts the EFS volume to the /mnt/efs directory during the first boot.  

```
#!/bin/bash
apt-get update
apt-get install -y amazon-efs-utils
mkdir -p /mnt/efs
mount -t efs -o tls fs-efs-id:/ /mnt/efs
echo 'fs-efs-id:/ /mnt/efs efs defaults,_netdev,tls 0 0' >> /etc/fstab

fs-efs-id is Placeholder.
```

### 3.4 CloudWatch

To ensure high availability, I configured Amazon CloudWatch to keep a constant watch on the health of the EC2 instance.

- Metric Monitoring: StatusCheckFailed metric.
- Automated Alerts: If the EC2 instance fails, the alarm status changes to ALARM. This triggers an Amazon SNS notification, which sends an immediate email alert to the administrator.
- Self-Healing: This setup allows for rapid response, ensuring that any downtime is minimized through automated alerts and recovery actions.

- Conditions:  
        Threshold type: Static  
        Whenever StatusCheckFailed is... Greater > than 0  
        Additional configuration: 1 datapoint in 5 minutes.
