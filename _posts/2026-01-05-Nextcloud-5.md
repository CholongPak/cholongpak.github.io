The final phase of the infrastructure setup is to install the container and deploy the Nextcloud application.

### 4.1 Installing Docker

Nextcloud AIO (All-in-One) runs as a set of Docker containers. I used the following commands to set up the environment on EC2 after connect using SSH:

SSH:

![ssh1](/assets/img/aws_cloud/ssh1.png)
![ssh2](/assets/img/aws_cloud/ssh2.png)

Commands:

```
sudo apt update
sudo apt install docker.io -y
sudo systemctl start docker
sudo systemctl enable docker
```

### 4.2 Preparing the Persistent Folder Structure

Before launching the Nextcloud container, I had to prepare the directory structure on the mounted EFS volume. This ensures that every component of the Nextcloud All-in-One (AIO) suite has a dedicated, persistent home.

1. Create the EFS Directory Tree within /mnt/efs

```
sudo su
mkdir docker
mkdir backup
cd docker
sudo mkdir -p /mnt/efs/docker/nextcloud_aio_{apache,collabora_fonts,database,database_dump,mastercontainer,nextcloud,nextcloud_data,redis}
```

![efs_directories](/assets/img/aws_cloud/efs_directories.png)

2. Mapping Docker Volumes to EFS (Bind Mounts)

By default, Docker volumes are stored locally on the EC2's EBS volume. To redirect this to the EFS folders I just created, I manually created local-persist volumes. This "binds" a Docker volume name to a specific physical path on the EFS mount point.

```
sudo docker volume create --driver local --name nextcloud_aio_mastercontainer -o device=/mnt/efs/docker/nextcloud_aio_mastercontainer -o type=none -o o=bind
```

![bind_mounts](/assets/img/aws_cloud/bind_mounts.png)

3. Verifying the Docker Volumes

```
Docker volume ls
```

![docker_volume](/assets/img/aws_cloud/docker_volume.png)

### 4.3 Launching Nextcloud All-in-One (AIO)

I deployed the [Nextcloud AIO Master Container](https://github.com/nextcloud/all-in-one). This container acts as the orchestrator, managing the lifecycle of all other necessary containers (Database, Redis, Apache, etc.)

```
sudo docker run \
  --init \
  --sig-proxy=false \
  --name nextcloud-aio-mastercontainer \
  --restart always \
  --publish 80:80 \
  --publish 8080:8080 \
  --publish 8443:8443 \
  --volume nextcloud_aio_mastercontainer:/mnt/docker-aio-config \
  --volume /var/run/docker.sock:/var/run/docker.sock:ro \
  ghcr.io/nextcloud-releases/all-in-one:latest
```

![aio1](/assets/img/aws_cloud/aio1.png)
![aio2](/assets/img/aws_cloud/aio2.png)

I accessed the AIO interface via https://rrcnextcloud1030.duckdns.org:8443.

**Troubleshooting Note: Slim Application Error**

![simple_application_error](/assets/img/aws_cloud/simple_application_error.png)

While setting up the Nextcloud Docker instance, a Slim Application Error was initially encountered, which prevented access to the NextCloud setup interface using the DNS. The problem was specifically triggered by running the recommended installation command from RRC Cloud course:

```
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh ./get-docker.sh
```

The issue was resolved by instead using: 

```
sudo apt install docker.io 
```
