# D9. Logging for Truth

## Challenge

So now we know how the data was exfiltrated - a shady commit in a GitHub repo. And, going by the reference logs, it looks like Erik is responsible!  

But Erik is the developer who gave us the compromised repository - and he made all the commits in the log. So is he really bad at covering his tracks? Or is he being framed?

We could use some proof...  

Luckily for us, GitHub keeps logs of all actions users do on the codebase - which is pretty helpful for situations like this! Personalyz imports the logs from GitHub and stores them in our log dashboard [Insightful Horizon](https://target-osd.chals.io/), so that's where you're headed now.  

Unfortunately, Erik didn't tell you *which* repository that .git directory came from, and he's been out of office and unreachable for the last few days. So you've got the audit logs for all the repositories he's worked on in the last six months to sift through to try and figure out what really happened here.  

**Objective**

Into the audit logs! Head over to the Insightful Horizon log dashboard at one of these servers:  
- [https://target-osd.chals.io](https://target-osd.chals.io/)  

You'll want to use the `audit-logs` index for this challenge.  
Dig deep and find the evidence - who *really* added that malicious code to the application?  
Once you think you have a solid case, use the IP address of the insider as the flag.

## How I found the flag

1. If the threat actor edited the code, I thought the action should be "merge" and the method should be "POST".
2. I tried to find the flag based on my initial idea. I filtered for "action: pull_request.merge" and "method: POST".
![filtered "merge" and "POST"](/assets/img/target2025/target2025_d9_1.png)
3. There were over 600 results; however, I had the name I obtained in the last challenge, "elesiuta". This person might have been framed, but the malicious commit still came from the account "elesiuta." So, I used this name to narrow down the results.
4. I filtered for "action: pull_request.merge," "method: POST," and "actor: elesiuta".
![filtered "merge", "POST", and "elesiuta"](/assets/img/target2025/target2025_d9_2.png)
5. Yes, there was a different IP address (an external IP). This was the flag.

**Flag: 241.17.22.80**
